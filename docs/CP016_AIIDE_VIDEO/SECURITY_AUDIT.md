# CP-016 AIIDE Video — Local Security Cross-check

**Release gate: local pilot / NO-GO automated production.**

Controls tested:

- Server-side auth and CSRF retained for generation and status updates.
- API key AIIDE from encrypted `video/aiide` pool; the browser only sees masked key metadata.
- Explicit opt-in flags and per-request cost consent; no automatic paid retries.
- A request is persisted as `submission_unknown` before the paid POST, to avoid double billing after crashes/timeouts.
- The key used for task submission is pinned by ID for all subsequent polling.
- Polling takes only provider task ID generated by the API; no arbitrary external URL from the browser.
- MP4 result URLs are HTTPS-only, exact approved host, redirect disabled; localhost/IP/private hosts rejected.
- Result capped at 120 MiB and checked for playable MP4/FFprobe duration/stream; files saved by SHA256.
- Status and job history never include API key or signed download URL.

Open risks requiring review:

- Exact AIIDE Seedance JSON profile not documented by the public `/v1/videos` examples (Sora/Veo only).
- Provider billing and actual quota are not observable from local tests.
- Multi-process concurrency and distributed budget controls are not supported by the local JSON ledger.
- Host allowlist must be set after verifying result CDN ownership; host allowlisting alone does not prevent every network-level DNS-rebinding issue.
- Signed URL delivery requires careful privacy handling; never paste URLs with embedded signed tokens into chat or public logs.
- Windows NTFS ACL permissions for `.local-private` must be checked manually.
