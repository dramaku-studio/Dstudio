# CP-002 — Database foundation and transactional run controls

Date: 2026-11-05
Status: **IMPLEMENTED IN SOURCE; DATABASE INTEGRATION UNVERIFIED**

## Implemented in this repository

- PostgreSQL 17 SQL migration: organization/user/membership/project, immutable production plans, approval decisions, production runs, run budget accounts, provider capability registry, reservations, append-only usage ledger, idempotency keys and durable outbox.
- Node service functions using a PostgreSQL-compatible `pg.Pool` connection: `approvePlan`, `createProductionRun`, `reserveGenerationInternal`, `settleGenerationInternal`, `markSubmissionUnknownInternal`.
- Organization-scoped membership checked inside transaction before plan approval and run creation. **Actor ID must come from trusted server-side authentication; this repo does not yet include an authentication provider or protected HTTP routes.**
- `SELECT ... FOR UPDATE` account locks, reserve+ledger+outbox in one transaction, and idempotent run creation. No external paid POST is issued.
- Dispatch blocked by default without a current `provider_capabilities` verification record; production deployments must populate only after controlled capability spike.
- Overrun is recorded at actual billed cost and prevents additional reservations; unknown submission blocks further spending until reconciliation.
- Domain hardening: unknown node types rejected, canonical snapshot hashing, in-memory overrun blocking, optional strict export version/selection check.
- Offline unit / scripted SQL tests and optional real PostgreSQL integration test; GitHub Actions CI prepared with PostgreSQL 17.
